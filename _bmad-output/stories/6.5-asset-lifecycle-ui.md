# Story 6.5: Large-Paste-to-TXT & Asset Lifecycle UI

**Epic:** E6 — UI Integration & Branch-Aware Experiences
**Pipeline:** 3 — Integration
**Depends-On:** 3.7, 5.1, 5.5, 5.6, 6.1
**Status:** Ready

## Context

Long pastes are automatically converted to `.txt` assets. The UI supports uploading assets, viewing assets preserved in deleted replies, and explicitly deleting them. Edit mode shows trailing assistant asset references with remove option.

**Affected files:**
- `src/components/composer.tsx` (paste handling)
- `src/components/asset-manager.tsx` (new — asset lifecycle UI)

**Dependencies:** Story 3.7 (char limit), Story 5.1 (asset upload), Story 5.5 (asset preservation), Story 5.6 (edit-mode assets), Story 6.1 (auth-gated UI)

## Acceptance Criteria

**Given** a paste > 200 chars in the composer
**When** it is submitted
**Then** it becomes a `.txt` asset shown as a reference in the message — FR-7, UX-DR5

**And** the UI supports uploading assets, viewing assets preserved in deleted replies, and explicitly deleting them — FR-12, FR-16, UX-DR8

**And** in edit mode, trailing assistant asset references are visible with a remove option — FR-17, UX-DR7

## Technical Notes

- Paste detection: `onPaste` event handler in composer
- Asset upload: file input or drag-and-drop
- Asset list: show assets with filename, size, delete button
- Deleted reply assets: show with "from deleted reply" indicator
- Edit mode: asset references from trailing assistant with remove button

## Definition of Done

- [ ] Paste > 200 chars converts to .txt asset
- [ ] Asset reference shown in message
- [ ] Asset upload UI (file input/drag-drop)
- [ ] Asset list with delete button
- [ ] Deleted reply assets preserved and shown
- [ ] Edit mode shows asset references with remove
- [ ] TypeScript compiles without errors
