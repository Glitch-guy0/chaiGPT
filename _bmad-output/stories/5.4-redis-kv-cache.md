# Story 5.4: Redis KV Cache for RAG Context Reuse

**Epic:** E5 — Assets & RAG
**Pipeline:** 2 — Core Logic
**Depends-On:** 5.3, 1.3
**Status:** Ready

## Context

Redis caches RAG context keyed by conversation ID. On cache hit, stored context is returned; on miss, embed + search Qdrant and cache with TTL. Route handlers remain stateless.

**Affected files:**
- `src/lib/cache/redis.ts` (implement E1 interface)
- `src/services/chat.service.ts` (cache integration)

**Dependencies:** Story 5.3 (retrieval logic), Story 1.3 (RedisCache interface)

## Acceptance Criteria

**Given** `lib/cache/redis.ts` implementing the E1 `RedisCache` contract
**When** `ChatService` requests context for a conversation
**Then** a cache hit returns stored context; on miss it embeds + searches Qdrant and caches with a TTL

**And** route handlers remain stateless and stores externalized — NFR-2

## Technical Notes

- Use `ioredis` or `redis` package for Redis client
- Cache key: `rag:context:{conversationId}`
- TTL: 5 minutes (configurable)
- Cache value: serialized context array
- Invalidate on new asset upload or asset deletion

## Definition of Done

- [ ] Redis client configured and connected
- [ ] Cache hit returns stored context
- [ ] Cache miss triggers embed + search + cache
- [ ] TTL-based expiration
- [ ] Cache invalidated on asset changes
- [ ] Route handlers stateless
- [ ] TypeScript compiles without errors
