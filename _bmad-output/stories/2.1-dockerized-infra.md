# Story 2.1: Dockerized Infra & Lifecycle Scripts

**Epic:** E2 — Foundation & Infra
**Pipeline:** 1 — Foundation Setup
**Depends-On:** 1.4
**Status:** Ready

## Context

The project needs Postgres + Qdrant running locally via Docker Compose with a named volume for asset storage. npm lifecycle scripts must bring up/tear down the full stack for dev and prod. This delivers the production-grade infra substrate (G6).

**Affected files:**
- `infra/docker-compose.yml` (new)
- `package.json` (modify — add scripts)
- `.env.example` (new or modify)

**Dependencies:** Story 1.4 (shared types/schemas exist for config alignment)

## Acceptance Criteria

**Given** the repository on a machine with Docker installed
**When** I run `npm run start:dev:infra`
**Then** a named Docker volume is created (if not exists) and Postgres + Qdrant start via Docker Compose

**And** `npm run start:dev` also starts the Next.js app on the host after infra is up

**And** `npm run stop:dev:infra` stops the containers and deletes the volume only if it was explicitly provided

**And** equivalent `start:prod`/`stop:prod` scripts build and run the full production stack

**And** externalized stores satisfy horizontal-scale and reversible-migration requirements — NFR-2, NFR-6

## Technical Notes

- Postgres: use `postgres:16` image, port 5432, persistent named volume
- Qdrant: use `qdrant/qdrant` image, port 6333, persistent named volume
- Named volume for assets: separate from DB volumes
- `.env.example` should list `DATABASE_URL`, `QDRANT_URL`, `CLERK_SECRET_KEY`, `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY`, `OPENAI_API_KEY`, `JINA_API_KEY`
- `start:dev:infra` should start infra in detached mode, then start the app
- `stop:dev:infra` should stop containers; only delete volumes if explicitly flagged

## Definition of Done

- [ ] `infra/docker-compose.yml` defines Postgres + Qdrant services
- [ ] Named Docker volumes for DB, Qdrant, and assets
- [ ] `npm run start:dev:infra` brings up infra + app
- [ ] `npm run stop:dev:infra` tears down containers
- [ ] `npm run start:prod` / `stop:prod` for production stack
- [ ] `.env.example` lists all required env vars
- [ ] Docker Compose starts cleanly with `docker compose up -d`
