# Story 2.3: Clerk Auth Middleware & Session Helper

**Epic:** E2 — Foundation & Infra
**Pipeline:** 1 — Foundation Setup
**Depends-On:** 1.4
**Status:** Ready

## Context

Clerk authentication gates all protected routes. Next.js middleware intercepts unauthenticated requests, and route handlers read the session via `auth()` from `@clerk/nextjs/server`. Auth overhead must stay under 50ms p95.

**Affected files:**
- `src/middleware.ts` (new or modify)
- `src/lib/auth/session.ts` (implementation of E1 interface)
- `.env.example` (add Clerk keys)

**Dependencies:** Story 1.4 (auth interface contract from E1)

## Acceptance Criteria

**Given** `@clerk/nextjs` is installed and keys are in `.env`
**When** an unauthenticated request hits a protected route
**Then** the request returns 401 / redirect — FR-3

**And** `src/middleware.ts` guards protected routes and route handlers obtain `userId` via the E1 `auth` contract (`auth()` from `@clerk/nextjs/server`) — FR-1, FR-23

**And** auth session resolution adds < 50 ms p95 overhead — NFR-3

## Technical Notes

- Install `@clerk/nextjs` if not present
- Middleware should protect all routes except `/`, `/sign-in`, `/sign-up`, `/api/webhook`
- `auth()` returns Clerk session; extract `userId` from `session.sub`
- Implement the E1 `auth` interface from Story 1.3
- `.env.example` should list `CLERK_SECRET_KEY`, `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY`
- Consider using Clerk's built-in middleware matcher config

## Definition of Done

- [ ] `@clerk/nextjs` installed and configured
- [ ] `src/middleware.ts` protects routes
- [ ] Unauthenticated requests return 401/redirect
- [ ] `auth()` helper returns `userId` from Clerk session
- [ ] Auth implements the E1 interface contract
- [ ] `.env.example` has Clerk keys
- [ ] Auth overhead < 50ms p95 (manual test or benchmark)
