# Story 3.7: 500-Char Limit & Large-Paste-to-TXT

**Epic:** E3 — Conversation & Message Core
**Pipeline:** 2 — Core Logic
**Depends-On:** 3.3
**Status:** Ready

## Context

Messages are capped at 500 characters. Pastes exceeding 200 characters are automatically converted to `.txt` assets and uploaded, with the message referencing the asset.

**Affected files:**
- `src/services/message.service.ts` (validation logic)
- `src/services/asset.service.ts` (paste-to-asset conversion)

**Dependencies:** Story 3.3 (ChatService send flow)

## Acceptance Criteria

**Given** a message draft
**When** its length exceeds 500 characters (hard cap) or a paste exceeds 200 characters
**Then** the over-length content is converted to a `.txt` asset and uploaded, and the message references it — FR-7

**And** the inline message body stays within the 500-char limit — FR-7

## Technical Notes

- Validate at message send time (before persisting)
- Paste detection: check if content was pasted (may need client-side flag)
- Asset creation: write to docker volume, embed via LangChain
- Message body truncated or replaced with asset reference
- Consider: should 500-char be a hard reject or auto-truncate?

## Definition of Done

- [ ] 500-char limit enforced on message content
- [ ] Paste > 200 chars converts to .txt asset
- [ ] Message references the created asset
- [ ] Inline body stays within 500 chars
- [ ] TypeScript compiles without errors
- [ ] Unit tests pass (Story 2.5)
