# Story 3.1: Concrete Entities & TypeORM Repositories

**Epic:** E3 — Conversation & Message Core
**Pipeline:** 2 — Core Logic
**Depends-On:** 2.2, 1.2
**Status:** Ready

## Context

Implement the concrete TypeORM repositories against the E1 interfaces. Repositories enforce `userId` scoping on every query and provide persistence for conversations, messages, and assets.

**Affected files:**
- `src/lib/db/repositories/conversation.repository.ts` (implement E1 interface)
- `src/lib/db/repositories/message.repository.ts` (implement E1 interface)
- `src/lib/db/repositories/asset.repository.ts` (implement E1 interface)

**Dependencies:** Story 2.2 (Postgres DataSource), Story 1.2 (repository interfaces)

## Acceptance Criteria

**Given** the E1 entity and repository interface definitions
**When** implementations are written
**Then** `ConversationRepository`, `MessageRepository`, `AssetRepository` implement the E1 interfaces and enforce `userId` scoping on every query — FR-2

**And** `AssetRepository` implements `save`, `findByConversation`, `delete` — FR-12

**And** `MessageRepository` implements `findByConversation`, `save`, `updateStatus` — FR-5, FR-6

**And** `ConversationRepository` implements `findById`, `findAll`, `save`, `updateStatus` — FR-2, FR-4

## Technical Notes

- Use TypeORM `Repository` pattern (注入 DataSource or EntityManager)
- Every `find*` method must include `where: { userId }` clause
- `findAll(userId)` should order by `updatedAt DESC` and limit to 50
- `updateStatus` should use TypeORM `update` method
- Consider using `@InjectRepository` if using DI, or直接 inject DataSource
