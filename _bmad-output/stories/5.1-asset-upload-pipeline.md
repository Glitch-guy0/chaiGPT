# Story 5.1: Asset Upload Pipeline (Volume + Embed + Delete Original)

**Epic:** E5 — Assets & RAG
**Pipeline:** 2 — Core Logic
**Depends-On:** 3.1, 1.3
**Status:** Ready

## Context

Users upload PDF/TXT/MD documents that get staged to a shared Docker volume, embedded via LangChain, and the original file deleted. An Asset row is persisted for tracking. Logical user isolation is at the DB layer.

**Affected files:**
- `src/services/asset.service.ts` (implement E1 interface)
- `src/app/api/assets/route.ts` (upload endpoint)

**Dependencies:** Story 3.1 (AssetRepository), Story 1.3 (QdrantStore interface)

## Acceptance Criteria

**Given** an authenticated user uploads a PDF/TXT/MD to `/api/assets`
**When** `AssetService.ingest(userId, convId, file)` runs
**Then** the file is staged to the shared named Docker volume, embedded via LangChain, and the original is deleted — FR-12

**And** an `Asset` row is persisted with `userId`/`conversationId`/`filename`/`mime`/`path` — FR-12, FR-2

**And** logical isolation is enforced at the DB layer via `Asset.userId`, not at the volume level — FR-12

## Technical Notes

- Use `multer` or Next.js built-in file handling for upload
- Stage to docker volume path (configurable via env)
- Embed via QdrantStore.upsertChunks (from E1 interface)
- Delete original file after successful embedding
- Asset row created with docker volume path
- MIME type detection for PDF/TXT/MD

## Definition of Done

- [ ] Upload endpoint accepts PDF/TXT/MD files
- [ ] File staged to docker volume
- [ ] File embedded via LangChain → Qdrant
- [ ] Original file deleted after embedding
- [ ] Asset row persisted with userId scoping
- [ ] TypeScript compiles without errors
- [ ] Unit tests pass (Story 2.5)
