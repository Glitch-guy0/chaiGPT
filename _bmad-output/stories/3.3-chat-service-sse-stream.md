# Story 3.3: ChatService Send with SSE Stream & Status Lifecycle

**Epic:** E3 — Conversation & Message Core
**Pipeline:** 2 — Core Logic
**Depends-On:** 3.2, 3.4
**Status:** Ready

## Context

ChatService handles the core send flow: persist user message, create trailing assistant message with `status: processing`, stream tokens via SSE, persist completed response, and handle explicit termination. This is the heart of the chat experience.

**Affected files:**
- `src/services/chat.service.ts` (implement E1 interface)
- `src/app/api/chat/route.ts` (SSE endpoint)

**Dependencies:** Story 3.2 (ConversationService), Story 3.4 (AiProvider)

## Acceptance Criteria

**Given** an authenticated user sends a `ChatRequest`
**When** `ChatService.send(req, userId)` runs
**Then** the user message is saved and a trailing assistant message is created with `status: processing` — FR-6

**And** tokens stream to the client via SSE live AND accumulate in a server-side buffer — FR-19

**And** on stream completion the assistant message is persisted with `status: complete` from the buffer — FR-6

**And** on explicit termination the assistant message content is `"user terminated the response"` with `status: stopped` — FR-6

**And** time-to-first-token is < 1 s — NFR-5

## Technical Notes

- Use `ReadableStream` for SSE in Next.js App Router
- Buffer tokens server-side while streaming to client
- `status: processing` → `complete` or `stopped` lifecycle
- AbortController for explicit termination
- Route handler validates request with `ChatRequestSchema` (FR-20)
- Consider using `TextEncoder` for SSE formatting

## Definition of Done

- [ ] `ChatService.send` saves user message + creates processing assistant message
- [ ] Tokens stream via SSE and accumulate server-side
- [ ] Stream completion persists with `status: complete`
- [ ] Termination sets content to "user terminated" + `status: stopped`
- [ ] TTFT < 1s (manual test)
- [ ] Route handler validates with Zod schema
- [ ] TypeScript compiles without errors
