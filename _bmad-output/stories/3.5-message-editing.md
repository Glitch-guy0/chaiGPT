# Story 3.5: Message Editing (Edit-Latest, In-Place)

**Epic:** E3 — Conversation & Message Core
**Pipeline:** 2 — Core Logic
**Depends-On:** 3.2
**Status:** Ready

## Context

Users can edit their latest user message in place without creating a branch. Only the most recent sibling is editable; earlier messages are disabled. The edit is content-only, same IDs.

**Affected files:**
- `src/services/message.service.ts` (implement E1 interface)

**Dependencies:** Story 3.2 (ConversationService for conversation context)

## Acceptance Criteria

**Given** the most recently created sibling message by the user
**When** `MessageService.editLatest(userId, convId, content)` runs
**Then** only that message and its trailing assistant reply are updated content-only with the same IDs — FR-11

**And** branching is unaffected and `lastMessageId` is unchanged — FR-10, FR-11

**And** only the latest user message is editable; earlier messages are disabled — brief #7

## Technical Notes

- Find latest user message by `createdAt DESC` within conversation
- Validate it's the most recent sibling (not already branched)
- Update `content` field only; preserve all other fields
- Trailing assistant reply also updated content-only
- `lastMessageId` on conversation remains unchanged
- Consider regenerating the assistant reply on edit (or leaving as-is)

## Definition of Done

- [ ] `editLatest` updates only the most recent user message
- [ ] Content-only update, same IDs preserved
- [ ] `lastMessageId` unchanged
- [ ] Earlier messages not editable
- [ ] TypeScript compiles without errors
- [ ] Unit tests pass (Story 2.5)
