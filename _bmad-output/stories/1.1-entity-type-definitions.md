# Story 1.1: Entity Type & TypeORM Decorator Definitions

**Epic:** E1 — Types & Contracts
**Pipeline:** 1 — Foundation Setup
**Depends-On:** — (none)
**Status:** Ready

## Context

The v2 data model introduces `userId` scoping, `parentId`/`rootConversationId` for branching, `status` lifecycle on messages, and a new `Asset` entity. This story delivers the TypeORM entity class definitions with field shapes and decorators — the fixed data model all later epics program against. No behavior is implemented; only shapes and signatures.

**Affected files:**
- `src/lib/db/entities/conversation.entity.ts` (modify existing or create new)
- `src/lib/db/entities/message.entity.ts` (modify existing or create new)
- `src/lib/db/entities/asset.entity.ts` (new)

**Dependencies:** None — this is the first story in the project.

## Acceptance Criteria

**Given** the v2 data model in PRD §9
**When** entity classes are declared
**Then** `Conversation` class defines `id` (uuid PK), `userId` (string, FK to Clerk sub), `rootConversationId` (uuid, nullable FK self-ref), `lastMessageId` (uuid, nullable FK to Message), `title` (string), `model` (string, nullable), `createdAt` (datetime), `updatedAt` (datetime) — FR-4

**And** `Message` class defines `id` (uuid PK), `conversationId` (uuid FK), `userId` (string FK), `parentId` (uuid, nullable FK self-ref), `role` (string enum: user|assistant|system), `content` (text), `model` (string, nullable), `status` (string enum: processing|complete|stopped), `createdAt` (datetime) — FR-5

**And** `Asset` class defines `id` (uuid PK), `userId` (string FK), `conversationId` (uuid FK), `filename` (string), `mime` (string), `path` (string — docker volume path), `createdAt` (datetime) — FR-12

**And** `status` is a string union type `processing | complete | stopped` exported as a shared type — FR-5

**And** all entities use `@PrimaryGeneratedColumn('uuid')` for id fields

**And** `updatedAt` on Conversation uses `@UpdateDateColumn()`

## Technical Notes

- Use TypeORM decorators (`@Entity`, `@Column`, `@PrimaryGeneratedColumn`, `@ManyToOne`, `@OneToMany`, `@UpdateDateColumn`, `@CreateDateColumn`)
- Self-referencing FKs: `Conversation.rootConversationId` → `Conversation.id`; `Message.parentId` → `Message.id`
- `Conversation.lastMessageId` → `Message.id` (nullable, set by service logic)
- `Asset.path` stores the docker volume path (logical isolation via `Asset.userId` at DB layer, not volume level)
- Export `MessageStatus` type union: `'processing' | 'complete' | 'stopped'`
- Export `Role` type union: `'user' | 'assistant' | 'system'`
