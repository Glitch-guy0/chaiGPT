# Story 1.2: Repository & Service Interface Definitions

**Epic:** E1 — Types & Contracts
**Pipeline:** 1 — Foundation Setup
**Depends-On:** 1.1
**Status:** Ready

## Context

With entity shapes defined (Story 1.1), we now declare the repository and service interface signatures that downstream epics implement against. Every repository query carries `userId` for scoping. Services define method shapes for ConversationService, MessageService, ChatService, and AssetService.

**Affected files:**
- `src/services/conversation.service.ts` (interface)
- `src/services/message.service.ts` (interface)
- `src/services/chat.service.ts` (interface)
- `src/services/asset.service.ts` (interface)
- `src/lib/db/repositories/conversation.repository.ts` (interface)
- `src/lib/db/repositories/message.repository.ts` (interface)
- `src/lib/db/repositories/asset.repository.ts` (interface)

**Dependencies:** Story 1.1 (entity definitions must exist for type references)

## Acceptance Criteria

**Given** the service layer design in `02-class.md`
**When** interface types are declared
**Then** `ConversationRepository` interface declares `findById(id, userId)`, `findAll(userId)`, `save(conv)`, `updateStatus(id, status)` — FR-2

**And** `MessageRepository` interface declares `findByConversation(convId, userId)`, `save(msg)`, `updateStatus(id, status)` — FR-2, FR-5

**And** `AssetRepository` interface declares `save(asset)`, `findByConversation(convId, userId)`, `delete(id, userId)` — FR-2, FR-12

**And** `ConversationService` interface declares `list(userId)`, `create(userId, input)`, `getById(id, userId)`, `branch(id, messageId, userId)` — FR-2, FR-4, FR-8

**And** `MessageService` interface declares `append(convId, userId, content)`, `editLatest(userId, convId, content)` — FR-10, FR-11

**And** `ChatService` interface declares `send(req, userId)`, `regenerate(messageId, userId)` — FR-6, FR-18

**And** `AssetService` interface declares `ingest(userId, convId, file)`, `remove(id, userId)` — FR-12, FR-16

**And** every repository query signature carries `userId` for scoping — FR-2
