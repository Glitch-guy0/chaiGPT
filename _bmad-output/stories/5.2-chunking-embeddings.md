# Story 5.2: Chunking & Per-Chunk Embeddings

**Epic:** E5 — Assets & RAG
**Pipeline:** 2 — Core Logic
**Depends-On:** 5.1
**Status:** Ready

## Context

Uploaded documents are chunked deterministically: PDFs page-by-page, TXT/MD at 2000 characters. Each chunk gets one embedding in Qdrant, with vector records referencing parent chunk + asset for citation.

**Affected files:**
- `src/lib/vector/chunker.ts` (new — LangChain splitters)
- `src/lib/vector/qdrant.ts` (embed/upsert logic)

**Dependencies:** Story 5.1 (asset upload pipeline)

## Acceptance Criteria

**Given** an uploaded PDF or TXT/MD
**When** chunking runs
**Then** PDFs are split page-by-page and TXT/MD at 2000 characters via LangChain splitters — FR-13

**And** Qdrant stores exactly one embedding per chunk — FR-14

**And** each vector record references its parent chunk index + asset id for citation — FR-14

## Technical Notes

- Use `@langchain/textsplitters` for chunking
- PDF: `PDFLoader` with page separation
- TXT/MD: `RecursiveCharacterTextSplitter` with 2000 char chunks
- Each chunk stored with metadata: `{ assetId, chunkIndex, conversationId }`
- Embedding via OpenAI embeddings (`text-embedding-3-small`)

## Definition of Done

- [ ] PDFs chunked page-by-page
- [ ] TXT/MD chunked at 2000 characters
- [ ] One embedding per chunk in Qdrant
- [ ] Vector records have assetId + chunkIndex metadata
- [ ] TypeScript compiles without errors
- [ ] Unit tests pass (Story 2.5)
