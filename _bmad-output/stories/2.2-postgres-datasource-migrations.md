# Story 2.2: Postgres DataSource & Reversible Migrations

**Epic:** E2 — Foundation & Infra
**Pipeline:** 1 — Foundation Setup
**Depends-On:** 2.1
**Status:** Ready

## Context

With Postgres running via Docker, we need a TypeORM DataSource configured for Postgres and reversible migrations that apply the v2 schema. SQLite is retired; existing data cleared for a fresh start.

**Affected files:**
- `src/lib/db/data-source.ts` (new or modify)
- `src/schema/entity/*.entity.ts` (migration entities)
- `src/schema/migrations/*.ts` (new — TypeORM migrations)

**Dependencies:** Story 2.1 (Postgres running), Story 1.1 (entity definitions for schema)

## Acceptance Criteria

**Given** Postgres is running via `start:dev:infra`
**When** I run the TypeORM migration command
**Then** the v2 schema from the E1 entity definitions is applied against Postgres and is reversible (down migration exists)

**And** SQLite is retired and existing local SQLite data is cleared for a fresh start — NFR-6

**And** the DataSource config reads `DATABASE_URL` from environment

## Technical Notes

- Configure TypeORM DataSource for Postgres (not SQLite)
- Use `synchronize: false` — schema managed by migrations only
- Migrations should be in `src/schema/migrations/` with timestamps
- Down migration must fully reverse the up migration (NFR-6)
- Remove or disable any SQLite-specific config/data-source
- Consider using `typeorm migration:generate` pattern for future migrations

## Definition of Done

- [ ] TypeORM DataSource configured for Postgres
- [ ] `DATABASE_URL` read from environment
- [ ] Up migration creates Conversation, Message, Asset tables with v2 schema
- [ ] Down migration fully reverses up migration
- [ ] SQLite config removed/disabled
- [ ] `npm run typeorm migration:run` applies schema successfully
- [ ] `npm run typeorm migration:revert` reverses cleanly
