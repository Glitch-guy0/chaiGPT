# Story 3.6: Regenerate Stopped Message (Re-run, Same ID)

**Epic:** E3 — Conversation & Message Core
**Pipeline:** 2 — Core Logic
**Depends-On:** 3.3
**Status:** Ready

## Context

A stopped assistant message can be regenerated: the same message ID is overwritten with a fresh completion. No branch is created. This allows retry without cluttering the conversation tree.

**Affected files:**
- `src/services/chat.service.ts` (add `regenerate` method)

**Dependencies:** Story 3.3 (ChatService with streaming)

## Acceptance Criteria

**Given** an assistant message with `status: stopped`
**When** `ChatService.regenerate(messageId, userId)` runs
**Then** the same message ID is set to `processing`, re-streamed via SSE, and overwritten with `status: complete` — FR-18

**And** no new sibling/branch is created — FR-18

## Technical Notes

- Validate message exists, belongs to user, and has `status: stopped`
- Set status to `processing`, re-stream, persist with `complete`
- Same message ID — no new row
- Build prompt from conversation history up to this point
- Consider: should the user content be re-submitted or just the assistant re-generated?

## Definition of Done

- [ ] `regenerate` overwrites same message ID
- [ ] Status lifecycle: stopped → processing → complete
- [ ] No new branch/sibling created
- [ ] TypeScript compiles without errors
- [ ] Unit tests pass (Story 2.5)
