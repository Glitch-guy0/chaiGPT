# Story 3.2: ConversationService (list/create/getById)

Status: ready-for-dev

## Story

As a user,
I want to list, create, and open my conversations,
So that I can manage my account-scoped chat history.

## Acceptance Criteria

1. **Given** an authenticated `userId`, **when** `ConversationService.list(userId)` is called, **then** only conversations with that `userId` are returned, ordered by `updatedAt` DESC, limited to 50. (FR-2)
2. **Given** a `userId` and optional `input` (`title?`, `model?`), **when** `ConversationService.create(userId, input)` is called, **then** a `Conversation` is persisted with `userId`, the supplied or default `title`, and the supplied or default `model`, with `createdAt`/`updatedAt` set. (FR-2, FR-4)
3. **Given** a conversation `id` and a `userId`, **when** `ConversationService.getById(id, userId)` is called and the conversation exists and belongs to that `userId`, **then** the conversation is returned. (FR-2)
4. **Given** a conversation `id` and a `userId`, **when** `ConversationService.getById(id, userId)` is called and the conversation exists but belongs to a different user, **then** the service signals a 404 (Not Found) — the resource must never be leaked across users. (FR-2)
5. **Given** a conversation `id` that does not exist, **when** `ConversationService.getById(id, userId)` is called, **then** the service signals a 404. (FR-2)
6. **Given** `create` is called without an explicit `model`, **when** the conversation is persisted, **then** `model` defaults to `gpt-4o-mini` (the AiProvider default, FR-22), and this default is sourced from one shared config constant so it can be swapped without touching the service. (FR-4, FR-22)
7. **Given** `create` is called without an explicit `title`, **when** the conversation is persisted, **then** `title` defaults to `"New Chat"` (matching `CreateConversationSchema` default in E1). (FR-4)
8. **Given** any inbound `input` to `create`, **when** it is processed, **then** `input` is validated against the E1 `ConversationSchema`/`CreateConversationSchema` Zod contract (FR-20) before persistence; invalid input is rejected before any DB write.
9. **Given** `list`/`create`/`getById` depend on Story 3.1 repositories, **when** this story is implemented, **then** they call `ConversationRepository.findAll(userId)`, `ConversationRepository.save(c)`, and `ConversationRepository.findById(id, userId)` respectively, never bypassing `userId` scoping. (FR-2, Story 3.1)

## Tasks / Subtasks

- [ ] Task 1: Implement `ConversationService.list(userId)` (AC: #1, #9)
  - [ ] 1.1 Inject `ConversationRepository` (constructed in Story 3.1) into `ConversationService` via constructor (matches `02-class.md` `ConversationService { -repo: ConversationRepository }`).
  - [ ] 1.2 Call `repo.findAll(userId)` and return only that user's conversations.
  - [ ] 1.3 Sort the result by `updatedAt` DESC and slice to a maximum of 50 items (enforce both ordering and limit in the service layer for determinism; repository may also apply ordering/limit — service is the guarantee).
  - [ ] 1.4 Return `Promise<Conversation[]>` conforming to the E1 `Conversation` entity type (`src/lib/db/entities/conversation.entity.ts`).

- [ ] Task 2: Implement `ConversationService.create(userId, input)` (AC: #2, #6, #7, #8, #9)
  - [ ] 2.1 Validate `input` with the E1 `ConversationSchema` / `CreateConversationSchema` Zod schema (`src/lib/validation/schemas.ts`); throw/return a 400-class validation error on failure (FR-20).
  - [ ] 2.2 Resolve `title` = `input.title ?? "New Chat"` and `model` = `input.model ?? DEFAULT_MODEL` where `DEFAULT_MODEL = "gpt-4o-mini"` (FR-22 default; see `AiProvider` default in Story 3.4).
  - [ ] 2.3 Construct a `Conversation` with `id` (uuid, generated by the entity/repository), `userId`, resolved `title`, resolved `model`, `rootConversationId: null`, `lastMessageId: null`, and `createdAt`/`updatedAt` set by TypeORM.
  - [ ] 2.4 Persist via `repo.save(conversation)`; return the persisted `Conversation` (`Promise<Conversation>`), matching E1 interface `create(userId: string, input: { title?: string; model?: string }): Promise<Conversation>` (`01/02-class` Story 1.2).
  - [ ] 2.5 Source `DEFAULT_MODEL` from a single shared config/constant (e.g. `src/lib/ai/langchain.ts` default export or a config module) so swapping it does not require editing the service (FR-22).

- [ ] Task 3: Implement `ConversationService.getById(id, userId)` (AC: #3, #4, #5, #9)
  - [ ] 3.1 Call `repo.findById(id, userId)` (the E1 `ConversationRepository.findById(id, userId)` signature that enforces `userId` scoping — FR-2).
  - [ ] 3.2 If the repository returns `null` (id missing OR id present but owned by another user), throw/return a 404 Not Found error. The service must NOT distinguish "not found" from "not yours" at the API boundary — both yield 404 to avoid leaking existence (AC #4, #5).
  - [ ] 3.3 If found and `userId` matches, return the `Conversation` (`Promise<Conversation>`).
  - [ ] 3.4 Define a typed `NotFoundError` (or use the shared HTTP-error type from `src/lib/utils.ts` / a `lib/errors` module) so the route handler can map it to an HTTP 404 without re-checking ownership.

- [ ] Task 4: Wire error handling & types (AC: #4, #5, #8)
  - [ ] 4.1 Ensure validation failures surface as a 400 (bad request) and ownership/missing as a 404; no raw TypeORM/DB errors leak to callers.
  - [ ] 4.2 Import `Conversation` type from `src/lib/db/entities/conversation.entity.ts` and request/input types from `src/types` + `src/lib/validation/schemas.ts` (no locally re-defined shapes — anti-pattern prevented by Story 1.4).
  - [ ] 4.3 Export the service from `src/services/conversation.service.ts` and register it for DI/construction by the route handlers (`ConversationsRoute`).

- [ ] Task 5: Unit tests (colocated `conversation.service.test.ts`) (AC: all)
  - [ ] 5.1 Mock `ConversationRepository` (Mock double per `02-class.md` test-doubles convention) so no network/DB is touched (FR-29, FR-30, NFR-8).
  - [ ] 5.2 Test `list`: returns only caller's conversations, ordered `updatedAt` DESC, capped at 50; a 51st older conversation is excluded.
  - [ ] 5.3 Test `create`: persists `userId`, defaults `title` to `"New Chat"` and `model` to `gpt-4o-mini` when omitted; honors explicit `title`/`model` when provided.
  - [ ] 5.4 Test `create`: rejects invalid input via Zod (FR-20) without calling `save`.
  - [ ] 5.5 Test `getById`: returns conversation owned by caller; returns 404 when missing; returns 404 when owned by another user (and never returns the cross-user record).
  - [ ] 5.6 Assert coverage ≥80% of the service (NFR-7, FR-31) — colocated `*.test.ts` next to the service as required by Story 2.5.

## Dev Notes

- **Architecture / layering (FR-21):** `ConversationService` lives in `src/services/conversation.service.ts` and is a *pure use-case orchestrator*. Dependency direction is `app (routes) → services → repositories (TypeORM)`. The service depends ONLY on the `ConversationRepository` interface (defined Story 1.2, implemented Story 3.1); it must NOT import TypeORM, the DataSource, or any integration module. There is **no port/adapter layer** — concrete repository is injected directly (approved coupling per `01-package.md` §3).
- **Interface contract to implement (from E1 / `02-class.md`):**
  - `ConversationService` methods (per `02-class.md` View A): `list(userId)`, `create(userId, input)`, `getById(id, userId)`, `branch(id, messageId)` — this story delivers `list`/`create`/`getById`; `branch` is Story 4.1.
  - E1 declared signatures (Story 1.2): `create(userId: string, input: { title?: string; model?: string }): Promise<Conversation>` and `getById(id, userId)`; `list` returns the caller's conversations. `ConversationRepository` interface (Story 1.2/3.1) declares `findById(id, userId)`, `findAll(userId)`, `save`.
  - `Conversation` entity fields (Story 1.1 / `07-entity.md`): `id`, `userId`, `rootConversationId?`, `lastMessageId?`, `title`, `model?`, `createdAt`, `updatedAt`.
- **Default model determination (FR-4, FR-22):** Default `model` is `gpt-4o-mini` — the same default used by `AiProvider` (Story 3.4, `src/lib/ai/langchain.ts`). Store this as a single shared constant (ideally exported from the AiProvider module or a `src/lib/config` module) and import it in the service so the model is swappable by changing ONE module, not the service logic (FR-22). Do NOT hardcode `gpt-4o-mini` inline in two places.
- **Default title:** `CreateConversationSchema` in Story 1.4 declares `title` default `"New Chat"`; `create` must use this same default.
- **Validation (FR-20):** Validate `input` against `ConversationSchema` / `CreateConversationSchema` from `src/lib/validation/schemas.ts` (Story 1.4) before any persistence. Validation is the E1 single-contract rule: no re-defined schema.
- **Error / 404 semantics (FR-2):** `getById(id, userId)` returns 404 for both "does not exist" and "exists but belongs to another user." Because `repo.findById(id, userId)` already scopes by `userId`, a cross-user or missing record both return `null`, so the service uniformly throws `NotFoundError` → HTTP 404. This prevents enumerating other users' conversation IDs (security: no existence leakage).
- **Limit & ordering:** `list` is capped at 50 and sorted `updatedAt` DESC. Implement the cap/sort in the service for a deterministic guarantee; the repository query MAY also apply `ORDER BY updated_at DESC LIMIT 50`, but the service MUST NOT trust the repository alone.
- **Testing standards (FR-29/FR-30/NFR-7/NFR-8):** Vitest, colocated `conversation.service.test.ts` next to the service. Mock `ConversationRepository` (declare a `MockConversationRepository` double consistent with `02-class.md` test-doubles). No real Postgres/network; coverage gate ≥80% enforced in CI (Story 2.5).
